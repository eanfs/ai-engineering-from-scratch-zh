「给我写一封营销邮件」，这是大多数人写提示词的方式。
结果是一坨泛泛而谈、根本没法用的东西。
同一件事，换一种写法，输出天差地别。
阶段 11，第 1 课：Prompt Engineering，提示词工程。
它不是花招，也不是绕路的小聪明。
它是人类意图和机器能力之间最主要的接口。
每次调用有三个部分：system、user、assistant prefill。
system 设定身份与规则，跨轮次持续，模型当成最高优先级。
prefill 可以给回复开头，直接逼出你要的格式。
「你是一名资深 Python 开发者」不是什么魔咒。
它是一个激活函数：把采样分布偏向训练数据里专家那一端。
同样的模型，同样的参数，激活的区域不同，质量就不同。
「你是个乐于助人的助手」，激活的是泛泛的中位数回答。
「你是 Stripe 专攻支付的资深后端工程师」，就窄得多、好得多。
但如果具体到「量子引力弦拓扑全球第一」，只会产出一本正经的胡说。
模糊版只有一句：给我们新产品写一封营销邮件。
具体版加了角色、受众、语气、字数、一个具体指标、结尾只留一个 CTA。
合法输出越少，拿到你想要那个的概率就越高。
「总结这篇文章」，可能是一段话、五百字长文，或者十个要点。
「用三个要点总结，每条一句话不超过二十词，只讲定量发现」。
前者把选择权交给模型，后者把选择权收回来。
第一种是角色：告诉它你是谁。
第二种是少样本：给它两三个例子，它照着学。
第三种是思维链：让它先写推理过程，再给答案。
护栏模式给模型画一个圈，圈外的问题一律拒绝。
实测：给一个 Python 助教加上护栏之后，被问别的领域时会明确说不。
这对面向用户的产品是必需的，不然它会替你做客服以外的一切。
改了提示词，输出变了，怎么知道是变好还是变坏？
建一个测试集，每个用例给一份预期输出，跑分。
实测里同一套用例，gpt-4o 五战全胜，另外两个模型各有所短。
幻觉：模型编了不存在的事实，通常是约束太少。
拒答：明明能答却拒绝，通常是护栏写得太宽。
格式违规：让它输出 JSON，它偏加上一句解释。
你写提示词时，最常漏掉哪一部分？
评论区说说：角色、示例，还是输出格式。
